Review servers create `secrets.token_urlsafe(32)` at startup and inject it into their widgets as `X-Mparanza-Review-Token`. It is used only on loopback (default `127.0.0.1`, also localhost/IPv6 loopback), is not sent to remote hosts by the review bridge, and expires with the server session. These random review tokens are not user credentials and are not read from the user's environment or files.
The deep-research widget also passes a `persistence_token` generated by its local MCP server with `crypto.randomBytes(32)`, bound to an expiring in-memory review context. This opaque reference is passed through host tool calls and may enter model context; it is not a user credential or remote authentication.
Scanner-listed review files: `modules/deep-research-validator/assets/deep-research-review-widget.html`, `modules/deep-research-validator/scripts/review_server.py`, `modules/prompt-optimizer/scripts/review_server.py`; installer: `scripts/_python_bootstrap.py`.
The flagged `.claude-plugin/plugin.json` contains plugin metadata, not these tokens or user credential values.
