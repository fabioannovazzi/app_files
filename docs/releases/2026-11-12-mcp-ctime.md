# MCP startup with unchanged package contents

The retained Windows incident `12bb8987-b1f0-4b80-8806-2db3e14be6c5`
records the Node gateway exiting before initialization when `ctimeNs` differed
between path and descriptor observations. The supplied diagnostic checked 2,230
manifest files: zero SHA-256 mismatches and 79 metadata differences. The OS
component causing those differences remains unidentified.

The shared verifier no longer treats `ctimeNs` alone as a reason to stop.
Device/inode, mode, size, modification time and link-count comparisons remain,
as do exact inventory, regular-file/ancestor checks, content hashes and manifest
rereading. Deterministic checks are appropriate here because byte equality and
file identity are mechanical properties; a status timestamp is not a content
digest. This change does not address the separate `catalog.lock` write denial.

Process-level regressions inject timestamp-only changes before and during reads
of both the catalogue and manifest, then verify MCP initialization and tool
discovery for Vera, Clara and Lucia. Negative cases retain rejection of changed
bytes, replacement identity and modification time. Windows CI runs these cases.
An initial regression failed against the original verifier before the fix.

Privacy source review: the change only affects local package verification. It
adds no network calls, recipients, model payloads, case inputs or retained logs.
Existing transport and workflow boundaries remain unchanged. Selected source
fingerprints and generated contracts are refreshed after this agent review;
manifest-only bindings do not represent a new professional or jurisdiction
assessment. These startup tests do not create a professional workflow privacy
report or establish its delivery/receipt acceptance.

The controlled regressions do not prove recovery on the affected Windows host.
Acceptance remains: install the corrected package, open a fresh Codex chat,
and retry the original task. No Marketplace publication or customer message is
part of this release.
