# Course privacy flow — 5 November 2026

## Observed

- Vera, Clara and Lucia router/report contracts required report preparation or display after professional execution without an explicit precedence rule for courses. Specialist reuse could therefore add reporting work to teaching.
- `courseware/execution.py` validates execution evidence, source identities and outputs; it does not require a privacy approval or privacy report.
- Archive catches reporting failures separately when starting and sealing runs. Existing fault-isolation tests exercise preservation of work and deliverables.
- `local_onboarding_case.py` maps the XML lesson to `client-file-preparation`. Selective reporting instead lists `fatture-xml-check`; this explains `not_applicable`, not parser failure. The existing real-parser tutorial regression succeeds with its managed XML input.
- No live campaign state or lesson files were accessed or changed. The reported worker-write and `catalog.lock` denials are context supplied with the task, not independently reproduced here.

## Change

All courses now take precedence over professional report preparation, display and verification defaults in the three routers, teaching skills and shared report contract. No participant privacy approval, fictitious-data confirmation, reporting detour or report-dependent checkpoint is introduced. Automatic local reports and honest diagnostics remain retained. A requested existing report remains accessible. Professional work with user documents enters a separate run using the existing handoff. Host permissions, data processing and transmission suppression are unchanged.

This is an instruction correction; it does not add a new execution bypass or change XML parsing. Privacy registers and generated contracts are refreshed for changed instruction/manifest identities. The review does not assert any new recipient, provider guarantee, zero model exposure or professional approval. Public function data-path explanations remain unchanged.

## Validation and limits

New regressions deliver course outputs with missing, unavailable, incomplete and not-applicable reporting and check that the precedence rule reaches all three products. Existing XML-parser, course, Archive isolation and package tests provide executable checks. CLI/package evidence cannot prove that a fresh host model will follow the new instructions in every conversation. Existing installations and already-open chats are separate acceptance targets; rebuilding or deploying downloads does not update them.
