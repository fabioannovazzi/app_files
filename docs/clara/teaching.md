# Impara con Clara

Release 0.1.194 adds mandatory first-use teaching to new and existing users
without an enrolled local profile, then reusable teaching on request. The native
OpenAI conversation discovers the professional's work and 3–4 relevant workflows.
One visible teaching chat explains by native voice; a second visible working chat
runs one real bounded specialist step at a time. The user controls native voice
and window setup. Local checkpoints do not prove a microphone or two windows
were operated; that needs native evidence or user confirmation.

The shared `desktop_teaching` stdlib runtime checks exact product identity, schema,
revisions, enrollment, paths, hashes and native handoff tokens. Semantic selection,
explanations, questions and understanding stay with the native model. Clara uses
its own advisory project contract; Lucia uses its private matter ledger where
required. The first example is followed by the user's own distinct practice.
After first use a show-only example can finish after confirmed understanding;
guided practice also requires the user's attempt or real-work application.

Profiles, summaries, examples, progress and optional feedback stay under the
OS-user product directory. Native OpenAI still processes the conversation and
selected content; local storage does not mean offline inference. There is no
custom voice/model API or Mparanza tutorial transport. Pending, inaccessible or
active teaching suppresses optional update polling. Tutorial receipt clients see
the existing compatibility exclusion marker. No audio or raw transcript is saved
by these helpers. Selecting real files creates a distinct normal assignment;
it does not authorize professional sending, signing or publishing.

Claude Cowork projections omit this feature. Actual local ChatGPT Work can reuse
the OS-user profile only with verified local access and required native controls;
cloud and mobile do not create substitute profiles. Existing completed records
survive plugin updates and project changes. Corruption requires recovery, never
silent reenrollment. The two products reject each other's stored profile even
when pointed at the same directory.

Validation distinguishes scripted state-machine participants from human voice
acceptance. Automated confirmations are test fixtures, never proof of a user's
participation or understanding. Release evidence is recorded separately.
