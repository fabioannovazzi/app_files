## Implemented scope

Both roles now have progressive guidance from intake, access and urgent measures through negotiations, changed facts, successful or unsuccessful outcomes, final report and residual work. Model reasoning selects the problem, evidence, existing capability and professional draft. No legal state machine, admissibility classifier or duplicate financial engine was introduced.

The local helper persists role-specific, version-bound closure handoffs. It requires the final report, its actual bases, documented receipts or explicit gaps, and residual task owners. Changed evidence reopens review; changing handoff metadata requires a new report version. Completing a run does not close the legal procedure.

The optional Mparanza route records an explicit browser decision under the existing authenticated account. It keeps only opaque case/node references, version hashes, role, decision, account and time. The client verifies the exact retained record over fixed HTTPS. This is account authentication, not a professional signature, proof of appointment or qualification. Plain model-authored JSON cannot create authenticated approval. The first reviewer account owns that case/role scope; no multi-user document-vault permission system is claimed. Regular drafting remains available without the hosted service.
