# Vera document personalization

## Scope and acceptance

Extend Vera's existing professional-drafting journey with optional, approved
document conventions, starting with documents prepared in response to tax
assessments. This is not an operational accertamenti/filing pipeline. The host
model interprets examples and corrections; Python enforces exact identities,
hashes, approval/version transitions and case-output boundaries.

1. Keep one explicitly selected personal/studio workspace outside plugin,
   repository, cache and client-run directories. No central profile service,
   account-wide automatic learning, or cross-customer synchronization.
2. Snapshot only selected examples. Record an exact document type and language;
   do not infer a procedure from the word accertamento. Produce a readable
   proposal and require professional approval of its exact digest.
3. Preserve old revisions, reject stale approvals, support disabling a profile,
   and keep revisions outside plugin upgrades. Corrections become a new proposal,
   never silent learning. Do not retain case facts as reusable instructions.
4. Bind only the selected approved conventions to a managed drafting run. Keep
   prior examples in the teaching workspace. Record the profile/version used;
   verify the resulting draft and its model-led review against exact hashes.
5. Integrate routing, drafting, validation, model-data reporting and public
   explanation. Package Codex, ChatGPT-upload and Cowork from canonical Vera.
6. Test isolation, approval, revision, tampering, disabling, run binding and a
   synthetic CLI journey. Validate package and CI, release and verify live bytes.

## Evidence boundary

Synthetic tests establish software behavior only. Francesco's selected examples
and a new case are still needed to measure correction effort and professional
quality. No personal style is shipped in the plugin. On hosts without local
storage, a one-session use of supplied conventions remains possible, but durable
learning is not claimed. Local storage is not local-only model processing.
