# Incident reporting implementation

The acceptance boundary is a diagnosable original failure, exact installation
and proven host linkage, an inspectable recovery timeline, and an actual
matching original-task outcome. An accepted envelope alone is insufficient.

Implementation sequence:

1. Extend transport and registry with capture completeness, technical frames,
   persistent host capabilities, operation/session identity, and recovery events.
2. Collect structured technical failures in the managed helper process and submit
   them with the original report. Retain arbitrary stderr for automatic host-model
   review; expose incomplete collection as a reporting failure.
3. Link Cowork guest installations through the native host helper with capability
   proof. Never infer physical machines from connector or guest UUIDs.
4. Expose installation/device counts, evidence gaps, age and original-episode
   progress to the operator monitor and update its read-only instructions.
5. Exercise real parser, validation, exception, startup and integrity failures;
   offline delivery, multiple installations, and original-task recovery.
6. Release, green CI, Git deployment, live synthetic acceptance, public package
   checks and temporary resource cleanup. No Marketplace action.

Mechanical matching and capture contracts are deterministic because their
correctness is directly verifiable. Root-cause diagnosis, relevance of retained
raw diagnostics and original professional-task acceptance remain model-led.

Core implementation now includes source-bound real-process events, exact operation
and optional input-receipt binding, explicit incomplete/overdue review state,
installation/global registry inspection, actual retry events and original-task
verification. Structured facts are distinct from completed semantic review.
Reporting interpreter and actual worker versions are separate fields.
Observed reporting-process versions and protocol capabilities are retained per
session separately from historical failure versions. Component dependency
checkers use the same verified-helper capture path; a real-process regression
confirms the component selector cannot re-enter Vera's top-level checker.
Server models now distinguish task-local reporter instances, persistent native
app profiles and host identities. App lookup preserves scoped original reports,
supplements, deliveries and exact outcome ownership across reporter instances.
It does not widen client permissions. The approved native bridge now uses the
same persistent host proof across native app profiles and accepts only the
existing reporter capability. It runs an indexed isolated reporter/collector
snapshot and returns public IDs or source-bound technical failure facts. Raw
stderr and device keys are not returned. Native broker observations are retained
separately from guest workflow versions; a broker update does not update a guest.
