# Archive chat association recovery

A real summary incarico was created without `originating_conversation`. The Archive service did not have a recoverable `CODEX_THREAD_ID`. Begin returned `conversation_linked: false`, but document publication succeeded and the caller overlooked the missing association. The affected incarico was repaired separately using the actual host-provided chat identity.

Begin previously computed `conversation_linked` from the presence of any saved conversation. On resumption, an older conversation therefore could falsely imply that the current chat was linked. Begin now confirms linkage only when an origin was supplied or recovered by the existing host environment fallback. Otherwise it returns `origin_unknown` with an explicit, idempotent repair instruction. Existing conversations and results remain intact.

Publication also returns a warning when no conversations are saved. This is separate from publication success and directs the caller to repair the association without republishing files. An existing conversation list alone does not verify the current chat; the continuity instructions require an exact host/thread comparison before claiming completion.

No identity is guessed from an Archive session, recent chat, title or file. An unavailable host identity remains an explicit limitation and does not block delivery. These changes reduce silent omission; they cannot guarantee that every host exposes a usable chat identity or that a model follows every repair instruction.
