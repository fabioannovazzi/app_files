# Vera reconciliation: implementation and component evidence

This change implements automatic semantic residual resolution in the maintained
Open-item raw runner and current-host model discovery for the existing Journal–Bank
semantic worker. It does not resume the paused evaluation campaign.

The model interprets references, descriptions, identity and competing explanations.
The Open-item engine replays exact source quotes and conserves positive decimal
allocations across invoices and bank movements. Currency, unit, entity, party,
payment direction, prior allocations and source/target residuals remain mechanical
controls. Supported allocations enter native rows, workbooks and assurance ledgers.
Partial and excess payments retain their residuals; ambiguity, conflicting evidence
and missing evidence never become paid items merely because amounts agree.

Open-item batches retain complete currency/entity perimeters, at most 120 rows and
48,000 prompt bytes. Over-cap perimeters are explicitly deferred, never truncated.
Source paths and unmapped columns are excluded; populated mapped business fields,
names and document identifiers are not anonymized. Requests, outputs and launch
receipts remain locally bound to the prepared population. The Archive producer
records its exact submission; unavailable field-origin measurements remain unknown.
This work does not claim completion of the separate Archive provenance acceptance.

## Host evidence

Shared owned policy supplies cost candidates, while Codex app-server model/list
supplies actual advertised models and efforts. No per-case visible chat or change
to the main chat model is introduced. A new model can be configured without changing
matching rules. Catalog availability is not a quality claim. Existing passive-invoice
callers retain their previous shared-worker default; reconciliation explicitly
uses discovery. Historical selection replay does not replace the original model
with a new catalog choice.

The actual macOS host advertised gpt-6-luna/high. Its observed runtime was Codex
Desktop 0.163.0-alpha.10.2 on Mac OS 27.0.0 arm64. The native execution capsule
verified its capability and allow/deny probes. Requested model/effort are retained;
this is not independent provider-side model attestation.

Antigravity 1.2.16 and its model catalog were observed. That establishes CLI/model
availability, not an isolated worker launch. Cowork native invocation was unavailable
in this session. Both distributions select their own host policy and report the
unimplemented isolated adapter; neither silently falls back to Codex. These hosts
are outstanding execution capabilities, not accepted implementations. Windows
catalog discovery was not exercised in this session.

## Component validation

A newly authored fictional live component run covered cumulative invoices 366+244
against a 610 receipt, a 125 partial payment against 500, two payments 40+60 against
100, and a 130 payment with an explicitly explained 30 excess against 100. All five
target allocations matched expectations. Wrong payer, equal-amount alternatives,
conflicting invoice reference and missing payment evidence remained unresolved.
The retained run also replayed successfully under the final allocation checks.
These are developer component cases, not an independent benchmark or fresh-session
end-to-end acceptance, and do not reuse the paused campaign as independent evidence.

The focused new-module tests passed 33 cases with 84.68% combined coverage
(capability selection 87%, Open-item semantic resolution 84%). A final Open-item
assurance and capability run passed 159 cases. The journal semantic focus passed
81 cases, and the separate historical-selection regression passed. Seven recovered
journal checks passed against stable source after the broader test run. The shared worker/projection
suite passed 146 cases, and the actual installed-runtime isolation regression
brought shared capsule coverage to 80.98%. Package checks passed 492 cases with
two conditional skips; a missing test fixture was resolved by using the normal
root fixture setup. Privacy checks passed all 108 cases at 90.30% coverage.

## Blocks encountered and recovery

| Block | Effect and evidence-based recovery |
| --- | --- |
| A list of multiple evidence IDs was not an Excel cell value | Stored the native field as a semicolon-delimited string; retained exact allocations in the ledger and tested multiple-payment workbooks. |
| Python and MCP exact implementation inventories omitted new source files | Synchronized the owned inventories; package startup and source integrity checks cover the new modules. |
| Assurance rejected the new retained semantic artifact namespace | Admit only the exact generated names with retained hashes and single-link checks; reject tampering and symlink parents. |
| An obsolete privacy test forbade host names in the Open-item explanation | Require the actual bounded worker path and unavailable-host limitation instead; all privacy checks pass. |
| Existing test expectations fixed the old file count and model configuration | Updated tests for the intended behavior; mock live catalogs in unit/CLI tests rather than querying an account. |
| Three receipt checks saw source edits during a broad test run | Reran the failed cases against stable source; all seven cases in that focused group passed. |
| Privacy fingerprints and teaching catalogs were stale after source edits | Regenerated owned catalogs and refreshed only affected source reviews before rebuilding packages. |
| Antigravity host-policy projection changed a teaching source hash | Bind the lesson to the exact projected bytes while retaining its original reviewed source hash. |
| Cowork projection retained the newly renamed Codex launch instructions | Project an explicit missing-adapter explanation and verify the packaged Cowork host policy. |
| Sandbox prevented native model discovery and Antigravity catalog inspection | Read-only escalated probes succeeded; no client data or model task was submitted by discovery. |
| Automatic approval rejected a broad restore in the original dirty checkout | Proved the exact owned patch against the initial clean-file snapshot, then reversed only that patch. Unrelated work remains preserved. |

Release version, source/package parity, server deployment, enabled installation and
fresh-chat professional acceptance are separate evidence. This document does not
claim Marketplace publication, installation updates or universal host acceptance.
