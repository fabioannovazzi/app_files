How to use this function

Prepare a professional communication with Vera

Learn to turn a topic and selected sources into a communication for a defined audience, then review the package before using it.

The explanation and a short practice take about 5–8 minutes. Processing and your questions can extend the session.

Start this course

  1. Open Codex on your computer with Vera installed and select @Vera in a chat.
  2. Copy the request below, paste it into the chat and send it.
  3. Turn on Codex voice in this chat. The assistant will guide you to open the second working chat in another window: listen and ask questions here, and watch the work and results there.

The fictional lesson files are already included in the plugin. You can also take the lesson in writing. This button copies the request; the lesson starts when you send it in Codex.

Two chats, one lesson

Speak with the teacher using the standard Codex voice. In the working chat, open in the window beside it, the function runs the case using the prepared files and shows its actual results. The teacher follows those results: interrupt, ask questions and change the pace whenever you need.

When to use it

Studio Riva wants to help its small business clients understand how to handle a data access request. We will prepare a short FAQ using a selected official source.

The complete communication workflow: objective and audience, sources, editorial decision, draft, checks, review and final files. The legal example lets you try the workflow; this lesson is not a GDPR course.

Files and request

Open brief-en.md for the assignment and requested format. Open source-en.md to inspect the selected official guide. The fictional firm starts without previous communications.

03

Run the workflow

  1. In the working thread, Vera establishes the audience, objective, language and channel and prepares the firm’s local workspace. In the voice chat, it explains what we will produce. You confirm the scope and where the work will be saved.
  2. Vera examines the source, decides what is useful and drafts the FAQ and proposed format. The current workflow checks claims and editorial quality separately. The voice explanation follows actual results, including any revision a check requires.
  3. Review the communication, sources and format. After the confirmations required by the workflow, open the actual generated package and find out how to use its files. Sending or publishing is a separate subsequent action.
During the lesson, the working chat runs the function and produces the result. If a step is unavailable, explain what is missing and keep the lesson incomplete.
04

Use the result

  1. FAQ in Markdown, for inspection and reuse after review.
  2. Technical basis, source references and records of checks and decisions.

Read the FAQ as a client: its audience and practical use should be clear. Check that claims match the source, limits remain visible and the format is the one accepted. The workflow may require revision or explain why no communication is warranted.

05

Pause and check

  1. State the audience you want to reach, the content they need and the format you want.
  2. Find the usable text and the source of one claim in the package; explain what you need to review before use.

These pauses help you learn how to use the function. They are not a technical detail quiz.

06
