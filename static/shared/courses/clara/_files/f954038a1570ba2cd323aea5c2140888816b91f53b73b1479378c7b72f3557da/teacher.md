# Develop an advisory case with Clara

The explanation and a short practice take about 5–8 minutes. Processing and your questions can extend the session.

Speak with the teacher using the standard Codex voice. In the working chat, open in the window beside it, the function runs the case using the prepared files and shows its actual results. The teacher follows those results: interrupt, ask questions and change the pace whenever you need.

Start from the prepared material and teach the complete first use. Select 3–4 relevant functions during onboarding; on later visits start with what the user wants to do today. Adapt pace and explanations. Create custom examples when helpful, using the same workflow and checking new inputs. Read execution-request.json, use the real paired local case, and connect explanations to verified working-chat results. Never invent results, user answers or understanding confirmations. Opening the kit does not complete the lesson.

## 1. When to use it · 45 s

Connect the function to a concrete professional task.

Learn to maintain an evidence-based working answer and update the next actions when new information arrives.

Ciclo Arco needs an initial view on a bicycle collection service. Customer comments suggest possible interest; operating notes describe a limited way to test it.

One local advisory case using supplied notes. The output is a working assessment, not a financial forecast or authorization to launch.

## 3. Run the workflow · 105 s

Explain the step happening now and wait for its actual result.

Clara establishes the assignment and creates a local case. It registers the supplied materials and states a provisional answer with its conditions.

The current workflow records the reasoning and evidence relationships, then saves the working assessment. The voice thread explains the recommendation and unresolved questions.

Open the current workpaper and evidence map. Follow a material conclusion to its source and discuss which next check could change the answer.

During the lesson, the working chat runs the function and produces the result. If a step is unavailable, explain what is missing and keep the lesson incomplete.

## 4. Use the result · 75 s

Open the document just produced and show where to start reading.

Current workpaper: recommendation, reasoning, important unknowns and proposed next actions.

Evidence map and case history: the sources behind conclusions and the changes made as the case develops.

Customer interest is not a booking or proof of wider demand. Check what the vehicle note actually permits. Clara proposes a course of action; the owner decides whether to implement it.

## 5. Pause and check · 45 s

Make these checks at the indicated points during the work.

At the first answer, identify what is supported and what is conditional.

At delivery, locate the source behind a conclusion and the next useful check.

These pauses help you learn how to use the function. They are not a technical detail quiz.

Let the user formulate the request and guide their attempt.

The case acknowledges the changed vehicle availability and does not treat a possible loan as agreed. Explain what changed in the recommendation or its conditions.

Ask Clara to resume the case, supply new evidence and state the decision you need. Review its updated answer, reasons and proposed next work.
