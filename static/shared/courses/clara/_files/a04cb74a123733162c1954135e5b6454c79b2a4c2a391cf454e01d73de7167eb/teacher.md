# Plan an advisory assignment with Clara

The explanation and a short practice take about 5–8 minutes. Processing and your questions can extend the session.

Speak with the teacher using the standard Codex voice. In the working chat, open in the window beside it, the function runs the case using the prepared files and shows its actual results. The teacher follows those results: interrupt, ask questions and change the pace whenever you need.

Start from the prepared material and teach the complete first use. Select 3–4 relevant functions during onboarding; on later visits start with what the user wants to do today. Adapt pace and explanations. Create custom examples when helpful, using the same workflow and checking new inputs. Read execution-request.json, use the real paired local case, and connect explanations to verified working-chat results. Never invent results, user answers or understanding confirmations. Opening the kit does not complete the lesson.

## 1. When to use it · 45 s

Connect the function to a concrete professional task.

Learn to turn a request into a clear assignment: the decision, evidence, deliverable and next work.

Ciclo Arco is considering a bicycle collection service. Before producing advice, we need to establish what the owner wants and what the available notes can support.

An initial assignment plan using the supplied fictional notes. The lesson ends at the handoff; the service recommendation belongs to the next workflow.

## 2. Files and request · 60 s

Open the files in the working window and show how to request the result.

Open assignment-en.md and notes-en.md. The first specifies the decision, reader and limits; the second contains customer statements and operational information.

Clara, plan this advisory assignment. Show what we need to decide, the proposed output, evidence we have, gaps and how the work should proceed.

## 3. Run the workflow · 105 s

Explain the step happening now and wait for its actual result.

Clara reads the request and selected notes, identifies any material clarification, and proposes the assignment in ordinary language.

Review the decision, scope, deliverable and missing evidence. Clara records the plan and checks it against the exact sources using the current planning workflow.

Read the summary and handoff. Identify the supported Clara workflow that would continue the assignment and what it must preserve.

During the lesson, the working chat runs the function and produces the result. If a step is unavailable, explain what is missing and keep the lesson incomplete.

## 4. Use the result · 75 s

Open the document just produced and show where to start reading.

Assignment contract and readable summary: what the work is for, its boundaries and intended output.

Validation report and handoff: whether the plan can proceed and what the next workflow should receive.

Check that the plan keeps the owner as reader, compares the requested options and does not invent prices, demand or authority to contact people. A valid plan is not an executed recommendation.

## 5. Pause and check · 45 s

Make these checks at the indicated points during the work.

Before drafting, identify the decision and intended reader.

At delivery, explain what will be produced next and which evidence remains missing.

These pauses help you learn how to use the function. They are not a technical detail quiz.

## 6. Try it yourself · 60 s

Let the user formulate the request and guide their attempt.

Use the practice files, including revised-assignment-en.md and update-en.md, to plan the owner’s narrower request: an action list for checking pilot feasibility. Keep the original plan.

The new plan reflects the changed objective and deliverable. Name the output and one condition that must be checked before a pilot can run.

Describe the decision, reader, desired output and available files. Review Clara’s scope and evidence plan before the selected workflow executes it.
