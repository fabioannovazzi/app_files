How to use this function

Import and review a transcript with Clara

Learn to add a transcript to a case, check who is speaking and preserve a usable version linked to its source.

The explanation and a short practice take about 5–8 minutes. Processing and your questions can extend the session.

Start this course

  1. Open Codex on your computer with Clara installed and select @Clara in a chat.
  2. Copy the request below, paste it into the chat and send it.
  3. Turn on Codex voice in this chat. The assistant will guide you to open the second working chat in another window: listen and ask questions here, and watch the work and results there.

The fictional lesson files are already included in the plugin. You can also take the lesson in writing. This button copies the request; the lesson starts when you send it in Codex.

Two chats, one lesson

Speak with the teacher using the standard Codex voice. In the working chat, open in the window beside it, the function runs the case using the prepared files and shows its actual results. The teacher follows those results: interrupt, ask questions and change the pace whenever you need.

01

When to use it

Sara has prepared a short note for Ciclo Arco’s next meeting. We start from a downloaded bundle and turn it into a registered case transcript.

This runs the local import and review route. The bundle is entirely fictional and contains no audio. Recording or transcribing new audio is a separate hosted step requiring a separate choice.

02

Files and request

Open context-en.md and case-notes-voice-input-en.json. The context explains provenance and the known speaker. You need not interpret technical fields: identify the bundle and target case for Clara.

  • case-notes-voice-input-en.json
  • context-en.md
Clara, import this note into the Ciclo Arco teaching case, preserve the original, check who is speaking and show the reviewed transcript. Do not add a decision about the service.
03

Run the workflow

  1. The working chat prepares the case and imports the bundle through the current workflow. Open the raw transcript and compare it with the context note; the voice chat explains where the files are stored.
  2. Clara reviews speaker attribution and wording without changing meaning. See how it identifies Sara and keeps price and route as unanswered questions.
  3. The workflow registers the reviewed version and links its source in the case. Open the final text and source reference; registration establishes the recorded wording, not the truth of every assertion.
During the lesson, the working chat runs the function and produces the result. If a step is unavailable, explain what is missing and keep the lesson incomplete.
04

Use the result

  1. Original transcript and bundle preserved in the local session.
  2. Reviewed transcript, attribution status and source registration in the case.

Check one passage word for word, the speaker’s name and the sentence saying the service has not been decided. There is no audio in this example, so you cannot verify the text against a recording.

05

Pause and check

  1. Before import, identify the bundle and target case.
  2. At delivery, locate one sentence in both the original and reviewed versions.

These pauses help you learn how to use the function. They are not a technical detail quiz.

06

Try it yourself

Import the practice bundle with two speakers into the same case. Ask Clara to retain Speaker 1 and Speaker 2 until their names are documented. Compare one turn with the original and preserve the first note.
  • case-notes-voice-practice-en.json
  • context-en.md

You can import a new note, find original and reviewed text and recognize uncertain attribution without inventing a name.

Specify the recording or bundle, language and destination. Use an ordinary folder when you only need to store a transcript; using it as case evidence also requires review and registration.

The kit contains fictional files and a prepared outline. Demonstration and practice results come from fresh runs of the current function.

The lesson library, profile and progress stay on your computer. They are not sent to Mparanza. Voice and content read in chat are processed by your OpenAI account: local storage does not mean offline inference.
