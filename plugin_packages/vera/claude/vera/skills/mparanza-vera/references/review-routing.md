# Review of saved Vera work

A work has zero or one user-facing review editor. A workflow may prepare inputs,
show files, or carry out a separately authorised operation; these are different
tasks. Do not ask the professional to review the same decision in two places.

Deliver routine results in the conversation with the requested documents. Open
an editor only when decisions need a table, source comparison, or actual
editing, or when the user asks to reopen it. Use `vera_open_review` with the exact
work reference or the three known Archive identities. Do not pass paths, row
contents or a whole review into chat to display a panel. The directory and chat
use the same editor registered in `ui/review-routes.json`. Opening does not
recalculate, save, apply, execute a filing or change case status. Chat-only
workflows do not call this tool. Source selection and ordinary model choices can
be settled in chat.

The registry marks each component as a shared item review, its own task in
the same panel, or no review. For example, a single bank exception can be
explained with its source in chat. If a reviewer asks to compare several
transactions, open the saved review. Studio-wide website, communications,
web automation, fusion and transformation reviews use their operator-issued
`work_ref` and `workflow`. Never infer a link from a similarly named client run.

The Vera product rule governs its included specialist modules. References in
standalone modules to launching a browser server, rendering a second MCP widget,
or using an editable HTML copy do not apply in Vera. Source qualification,
recorded decisions, privacy boundaries, preparation and domain validation still
apply. Intentionally separate actions such as preparing sources or executing an
approved archive plan remain available in the same work. If the host lacks the
editor, deliver the result and its outstanding issues in chat/files. Do not
promote a browser copy, workbook tab or second form as its replacement editor.
