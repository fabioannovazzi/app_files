# Centrale Rischi Review

## Optional native Codex workspace

An owned `centrale-rischi-review` run can explicitly select registered digital
PDF/tabular sources, inspect every retained JSON artifact by exact member pages,
propose pending mappings, calculate after a separate named timestamped human
mapping review, and conserve an evidence-linked draft report. Read
`../vera/references/native-workspace.md` for the shared ownership contract.

The exact signed user-issued CR grant permits only its literal question plus
the public bounded inspection or calculated `model_context.json` and template.
The panel can navigate all parsed table rows and observed mapping keys with
`vera_workspace_cr_source`. An explicit signed page question additionally
authorizes only that complete row/value page, returned as `selected_source_page`
by `vera_workspace_cr_model_context`. Read its exact columns, offsets, row counts
and coverage; other complete pages have not automatically entered context.
The public bounded inspection remains included. Full cells, counterparties,
amounts and PDF-normalized provenance can reach the selected OpenAI model;
this route is not anonymized or local-only. Observed keys use the public
calculator's text normalization without assigning semantic classes.
Use `vera_workspace_cr_model_context`, then stage the complete proposal with
`vera_workspace_cr_stage` using the freshly read `proposal_revision`. Never
change recipe provenance or its pending `mapping_review`, invent missing
value mappings, claim complete source reading from a preview or selected page, or
describe a model proposal as human approval. Unknown source coverage requires
further evidence in the maintained specialist workflow before mapping review.
PDF-normalized rows are not proof of visual review against the original PDF.
Commentary uses the exact analysis SHA and existing evidence references.

The app-only recipe editor can recover locally saved incomplete mappings for
one exact recipe grant, even before a model proposal exists. It presents all
inspected column choices and paginates observed original/residual duration and
risk keys; the professional chooses each public class. Blank choices remain
pending. Changing table or a duration/risk column explicitly clears its draft
mappings. Fixed provenance and pending mapping_review cannot be edited.
Draft/proposal compare-and-swap refuses concurrent overwrites; changed model
proposals leave earlier draft bytes available for explicit discard. Conserving
a draft proposal retains history and does not calculate or grant model access.
The separate named review and calculation confirmation are never restored.
The editor also recovers the exact observed-value field/page selector under the
same saved pending recipe; page reopening does not grant model access. App-only
proposal history paginates the grant's exact retained hashes without inventing
creation dates. Full historical recipe/commentary readback checks the hash and
original pending provenance or analysis reference. Historical tickets cannot
authorize calculation/finalization. A historical recipe may explicitly become
a new pending draft only under the displayed draft/proposal CAS; an existing
draft is preserved. The current proposal remains unchanged until conservation.

App-only source-selection and literal-question drafts remain separate from
inspection and model grants. The panel recovers all selected registered input
IDs across intake pages, and the exact inspected source-navigation page.
Unsent questions are retained verbatim for their exact revision or source-page
selector; another page has its own question. Signed owner/run/source scope and
draft CAS refuse foreign or concurrent writes. Saving or reopening a draft
does not inspect inputs, issue model authorization or restore confirmation.
Only an explicit later inspection or chat request invokes those existing tools.

Only app-selected full proposals invoke the unchanged calculation/finalization
producers. Reconciled mode remains unsupported. Earlier phases, blocked outputs
and all normal output formats remain retained. Uncertain or changed outputs
require recovery before new execution or Archive closure. Reports remain
`draft_pending_professional_review`; no rating, professional approval,
transmission or run completion is added.

Native UI availability is optional. Without these tools, follow the complete
module skill below and its unchanged file-based workflow. In Cowork, retain
the module's explicitly connected-file restrictions; do not claim a portable
Codex Studio Archive run or require native MCP for ordinary professional work.
