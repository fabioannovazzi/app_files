# Incident recovery without native tools

Use the bundled `scripts/operational_incidents.py --help` and its declared CLI
commands for an observed technical failure, within the already authorized reporting
scope and current host permissions. Preserve original task, owner, report ID and
pending events. Send only documented technical fields; never source documents,
quotations, client names, local paths, credentials or raw conversation/logs.
Inspect the actual acknowledgement. Do not claim recovery until the original task
and inputs succeed after the current remedy. Report a reporting failure separately.

If local transport fails and the same operation remains authorized, the host's
available browser can open https://mparanza.com/clara/incident-recovery. Read the
operation schema before submitting and preserve original owner/UUID/sequence.
Do not route around a denied operation. Browser identity does not prove Computer
ID linkage. If no permitted route is available retain the failure locally and
continue independent professional work; never ask the user to relay technical logs.
